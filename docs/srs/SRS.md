## 1 引言

### 1.1 目的

本文档定义 XTodoY v1.0 的功能需求、外部接口需求、非功能需求与数据需求，作为界面原型设计（P2）、技术设计（P3）、开发（P4–P6）与测试验收（P7）的唯一需求基线。

读者：产品负责人、设计、开发、测试。

### 1.2 范围

XTodoY 是一款面向 PC 桌面端的单用户、纯本地待办事项软件，提供：

- 待办事项的记录与手动勾选完成；
- 事项日期 / 时间与循环规则；
- 事项提醒，默认通过操作系统通知推送；
- 多级标签、按标签分类浏览与标签管理；
- 低资源占用的系统托盘常驻；
- 显示今日待办数量的桌面悬浮窗；
- 按日 / 周 / 月统计完成情况；
- 浅色 / 深色 / 跟随系统主题。

**不在 v1.0 范围内**：账号与云同步、多设备、协作共享、移动端、子任务、日历视图、自然语言输入、iCal 导入导出、邮件 / Webhook 等非系统通知渠道。

### 1.3 术语与缩写

| 术语 | 定义 |
|---|---|
| 待办 / 事项（Todo） | 用户记录的一条待处理事情，至少包含标题 |
| 截止日期（Due Date） | 事项计划完成的日期；可附带具体时间，也可为"全天" |
| 无日期事项 | 未设置截止日期的事项 |
| 逾期 | 未完成且截止时间早于当前时间的事项（全天事项以截止日期 23:59:59 为界） |
| 循环事项 | 带循环规则的事项，完成一次后自动进入下一次 |
| 实例（Occurrence） | 循环事项某一次计划发生的日期 |
| 循环规则 | 描述循环方式的规则，内部以 RFC 5545 RRULE 子集存储 |
| 提醒（Reminder） | 在指定时刻向用户发出的通知；一个事项可有多个 |
| 稍后提醒（Snooze） | 收到提醒后推迟一段时间再次提醒 |
| 补发 | 因关机 / 休眠 / 程序未运行而错过的提醒，在程序恢复后发出 |
| 标签（Tag） | 用户自定义分类，可组织为父子树 |
| 标签路径 | 从根到某标签的完整层级，如 `工作 / 项目A / 设计` |
| 完成记录（Completion Log） | 每次勾选完成产生的一条记录，是统计的数据源 |
| 今日待办 | 见 FR-FLT-03 的口径定义 |
| 主窗口 | 软件的主界面窗口 |
| 悬浮窗 | 置顶显示今日待办数量的小窗口 |
| 托盘 | 操作系统任务栏通知区域中的程序图标 |
| MoSCoW | 优先级：M = Must（必须）、S = Should（应该）、C = Could（可以）、W = Won't（本期不做） |

## 2 总体描述

### 2.1 产品视角

XTodoY 为独立的桌面应用，不依赖任何服务器。系统由以下部分构成：

```
┌──────────────┐  ┌────────────┐  ┌──────────────┐
│   主窗口      │  │   悬浮窗    │  │  托盘图标/菜单 │
└──────┬───────┘  └─────┬──────┘  └──────┬───────┘
       └─────────────────┼─────────────────┘
                 ┌───────┴────────┐
                 │ 后台核心（常驻） │── 系统通知
                 │ 数据 / 提醒调度  │── 开机自启
                 └───────┬────────┘
                   本地 SQLite 数据库
```

主窗口关闭后，后台核心、托盘与悬浮窗（若开启）继续运行，负责按时提醒与今日待办计数。

### 2.2 产品功能概要

| 编号 | 模块 | 概要 | 对应章节 |
|---|---|---|---|
| F1 | 待办管理 | 增删改查、勾选完成、排序、搜索 | 3.1 |
| F2 | 时间与循环 | 截止日期 / 时间、循环规则 | 3.2 |
| F3 | 提醒 | 多提醒、系统通知、稍后提醒、补发 | 3.3 |
| F4 | 标签 | 多级标签、多标签挂载、按标签浏览 | 3.4 |
| F5 | 标签管理 | 树形管理、拖拽、合并、删除策略 | 3.5 |
| F6 | 后台常驻 | 托盘、关闭到托盘、单实例、自启 | 3.6 |
| F7 | 悬浮窗 | 今日待办数、拖动、点击唤起 | 3.7 |
| F8 | 统计 | 日 / 周 / 月完成统计 | 3.8 |
| F9 | 外观与设置 | 主题、设置项、数据备份 | 3.9 |

### 2.3 用户特征

- 主要用户：在 PC 上工作 / 学习、需要管理日常任务的个人用户；
- 具备基本电脑操作能力，无需培训即可使用；
- 偏好鼠标与键盘混合操作，部分用户重度使用键盘。

### 2.4 运行环境

| 项 | 要求 |
|---|---|
| 主要平台 | Windows 10（21H2 及以上）/ Windows 11，x64 |
| 次要平台 | macOS 12+、主流 Linux 桌面（可构建、基本可用，不作为 v1.0 验收重点） |
| 硬件 | 双核 CPU、4 GB 内存、200 MB 可用磁盘 |
| 显示 | 1366×768 及以上，支持 100%–200% 缩放与多显示器 |
| 网络 | 不需要 |

### 2.5 设计与实现约束

- C-1 应使用主流跨平台桌面框架，项目已选定 Electron + React + TypeScript。
- C-2 数据应仅存储在本机用户数据目录，使用 SQLite。
- C-3 提醒默认使用操作系统自带的通知渠道。
- C-4 界面应同时支持浅色与深色模式。
- C-5 界面原型应使用 ui-ux-pro-max 插件设计，开发实现以评审通过的原型与设计令牌为准。
- C-6 源代码使用 git 管理，远程仓库 `https://github.com/AhDaii/XTodoY.git`。
- C-7 界面语言 v1.0 为简体中文；文案集中管理，为后续多语言预留。

### 2.6 假设与依赖

- A-1 用户未在系统中禁用本软件的通知权限；若被禁用，软件应能提示（见 FR-REM-09）。
- A-2 系统时钟基本准确；时区以系统设置为准。
- A-3 Windows 专注助手 / 勿扰模式可能屏蔽通知，属于系统行为，软件仅提供提示与补充渠道。

## 3 功能需求

每条需求格式：描述 → 输入 / 处理 / 输出（必要时）→ 优先级 → 验收标准（AC）。

### 3.1 F1 待办管理

**FR-TODO-01 新建待办** — M
- 描述：用户可在列表顶部的快速输入框输入标题并回车新建待办；也可通过"新建"按钮或快捷键 `Ctrl+N` 打开完整编辑面板。
- 输入：标题（必填，1–200 字符，去除首尾空白后不可为空）；可选：备注、截止日期 / 时间、循环、提醒、标签、优先级。
- 处理：在当前视图上下文中预填属性——在"今天"视图新建则截止日期预填今天；在某标签视图新建则预挂该标签。
- 输出：新待办出现在当前列表，焦点保持在快速输入框便于连续录入。
- AC：① 空标题回车不创建且不报错；② 超过 200 字符时阻止输入并提示；③ 在标签视图新建的待办自动带该标签。

**FR-TODO-02 编辑待办** — M
- 描述：单击待办打开右侧详情面板，可修改全部属性；修改即时保存（无"保存"按钮），`Esc` 关闭面板。
- AC：修改任一字段后关闭再打开，数据保持；程序崩溃重启后已输入内容不丢失（容忍最后 1 秒内的输入丢失）。

**FR-TODO-03 勾选完成 / 取消完成** — M
- 描述：每个待办前有一个圆形单选框。用户单击单选框将待办标记为完成；再次单击（在"已完成"视图或已完成分组中）取消完成。
- 处理：
  - 普通事项：状态置为已完成，记录完成时间，写入一条完成记录；
  - 循环事项：见 FR-REC-05；
  - 完成后在列表中以删除线 + 弱化样式显示约 1 秒后移入"已完成"分组，并在底部显示"已完成 · 撤销"提示 5 秒。
- 输出：今日待办计数、悬浮窗、托盘提示同步更新（≤ 1 秒）。
- AC：① 勾选后 1 秒内悬浮窗数字变化；② 点"撤销"恢复为未完成且删除对应完成记录；③ 取消完成后统计中的对应完成记录被移除。

**FR-TODO-04 删除待办** — M
- 描述：可在右键菜单、详情面板或按 `Delete` 删除待办；删除后显示"已删除 · 撤销"提示 5 秒。
- 处理：**[决策]** 删除为软删除，进入"回收站"，保留 30 天后自动清理；回收站中可恢复或永久删除。
- AC：① 撤销后待办及其标签、提醒完整恢复；② 删除的待办不再触发提醒；③ 回收站中超过 30 天的事项在程序启动时被清理。

**FR-TODO-05 智能视图** — M
- 描述：侧边栏提供以下固定视图：
  | 视图 | 内容 |
  |---|---|
  | 今天 | 截止日期为今天的事项（未完成在上，今日已完成折叠在下）；逾期事项不在此视图，见"计划"视图的逾期分组 |
  | 计划 | 所有有截止日期的未完成事项，按日期分组（逾期 / 今天 / 明天 / 本周 / 以后） |
  | 全部 | 所有未完成事项（含无日期） |
  | 已完成 | 已完成事项与循环事项的完成记录，按完成日期倒序分组 |
  | 回收站 | 已删除事项 |
- AC：每个视图显示事项数量徽标（回收站除外），与实际列表数量一致。

**FR-TODO-06 排序** — S
- 描述：列表支持排序方式：手动（拖拽）、截止时间、优先级、创建时间、标题；每个视图独立记忆排序方式。
- AC：手动拖拽排序后重启程序顺序保持。

**FR-TODO-07 优先级** — S
- 描述：事项可设置优先级：无 / 低 / 中 / 高，以单选框边框颜色区分。
- AC：深色与浅色模式下优先级颜色均可辨识（对比度 ≥ 3:1）。

**FR-TODO-08 搜索** — S
- 描述：`Ctrl+F` 聚焦搜索框，按标题与备注模糊匹配，范围为全部未完成与已完成事项（不含回收站）。
- AC：1000 条事项时输入后 200 ms 内出结果。

**FR-TODO-09 批量操作** — C
- 描述：`Ctrl/Shift + 单击` 多选后可批量完成、删除、设置标签、设置日期。

### 3.2 F2 时间与循环

**FR-REC-01 截止日期与时间** — M
- 描述：事项可设置截止日期；可选择"全天"或指定时间（精确到分钟）。提供快捷选项：今天、明天、下周一、自定义日期。
- AC：① 可清除日期变为无日期事项；② 全天事项在列表中只显示日期，非全天显示日期 + 时间；③ 逾期事项日期以警示色显示。

**FR-REC-02 循环规则** — M
- 描述：事项可设置循环规则，支持：
  | 类型 | 参数 | 示例 |
  |---|---|---|
  | 每天 | 间隔 N 天 | 每 2 天 |
  | 每周 | 间隔 N 周 + 指定星期（多选） | 每周一、三、五 |
  | 每月 | 间隔 N 月 + 指定日（1–31 或"最后一天"） | 每月 15 日 |
  | 每年 | 间隔 N 年 + 月日 | 每年 3 月 8 日 |
  | 工作日 | 周一至周五 | — |
- 约束：设置循环必须先有截止日期；未设日期时选择循环，自动以今天为首个实例日期。
- AC：规则以自然语言摘要显示（如"每周一、三、五"），并可预览后续 5 次实例日期。

**FR-REC-03 循环结束条件** — S
- 描述：循环可设置结束条件：永不 / 于某日期结束 / 重复 N 次后结束。
- AC：达到结束条件后完成最后一次实例，事项变为普通已完成事项，不再生成新实例。

**FR-REC-04 月末与无效日期** — M
- 描述：**[决策]** 每月指定日在当月不存在时（如 31 日之于 2 月），该月实例落在当月最后一天；每年 2 月 29 日在非闰年落在 2 月 28 日。
- AC：单元测试覆盖 1/31 → 2/28(29) → 3/31 的序列。

**FR-REC-05 循环事项的完成语义** — M
- 描述：**[决策]** 采用"单条记录、日期前进"模型：
  1. 用户勾选循环事项 → 写入一条完成记录（记录本次实例日期与完成时间）；
  2. 事项截止日期前进到下一个实例日期，保持未完成状态，提醒按新日期重新计算；
  3. 下一个实例日期按 **原计划日期** 计算（而非完成日期）；若计算结果仍早于今天，则继续前进到第一个 ≥ 今天的实例（逾期期间错过的实例不补做、不计为完成）；
  4. 列表中短暂显示完成动画后，事项以新日期出现在相应位置。
- AC：① 每周一循环的事项在周三完成，下一实例为下周一；② 逾期 3 周的每周事项完成后下一实例为本周或下周的对应日期，完成记录仅 1 条；③ "撤销"会删除该完成记录并把日期回退到原实例日期。

**FR-REC-06 跳过本次** — S
- 描述：循环事项可"跳过本次"，日期前进到下一实例但不写完成记录。

**FR-REC-07 编辑循环规则** — M
- 描述：修改规则只影响当前及以后的实例；历史完成记录不变。
- AC：修改规则后统计中的历史数据不变。

**FR-REC-08 时区与夏令时** — M
- 描述：所有日期时间以系统本地时区解释与计算；系统时区变更后，按新时区重新计算提醒触发时间。
- AC：模拟时区切换后，"每天 9:00"提醒在新时区 9:00 触发。

### 3.3 F3 提醒

**FR-REM-01 设置提醒** — M
- 描述：事项可添加一个或多个提醒（上限 5 个），提醒类型：
  - 相对截止时间：准时、提前 5 / 15 / 30 分钟、1 / 2 小时、1 天、自定义（分钟 / 小时 / 天）；
  - 绝对时间点：指定某日某时刻。
- 约束：相对提醒需要截止日期；全天事项的"准时"指当天的"全天事项默认提醒时间"（FR-SET-04，默认 08:30），"提前 1 天"指前一天该时间。
- AC：① 同一事项不可添加两个触发时刻相同的提醒；② 删除截止日期时，相对提醒被移除并提示用户。

**FR-REM-02 默认提醒** — S
- 描述：设置中可配置新建带时间事项的默认提醒（默认：准时），用户可在单个事项中修改。

**FR-REM-03 系统通知推送** — M
- 描述：提醒到时，通过操作系统通知中心推送通知，内容：标题 = 事项标题；正文 = 截止时间 + 标签路径（若有）+ 备注首行（截断 60 字符）；图标 = XTodoY 图标。
- AC：Windows 10 / 11 上通知出现在操作中心并在其中保留。

**FR-REM-04 通知操作** — M
- 描述：Windows 通知提供操作按钮：「完成」「稍后提醒」；单击通知正文打开主窗口并定位到该事项。
- 处理：「完成」等同于 FR-TODO-03 的勾选完成；「稍后提醒」按默认稍后时长推迟（FR-REM-05）。
- AC：主窗口关闭状态下点击「完成」，事项被完成且悬浮窗计数更新，不弹出主窗口。

**FR-REM-05 稍后提醒** — M
- 描述：稍后提醒时长默认 10 分钟，设置中可选 5 / 10 / 15 / 30 / 60 分钟；同一提醒可多次稍后。
- AC：选择稍后后在设定时长后再次收到通知，误差 ≤ 5 秒。

**FR-REM-06 提醒准时性** — M
- 描述：程序运行期间，提醒应在触发时刻 ±5 秒内发出；调度不得采用高频轮询。
- AC：连续 24 小时测试 100 个随机提醒，全部在 ±5 秒内发出。

**FR-REM-07 错过提醒的补发** — M
- 描述：**[决策]** 程序启动、系统从休眠 / 睡眠唤醒、系统时间被向前调整时，检查期间错过的提醒：
  - 过去 24 小时内错过的提醒：补发；超过 3 条时合并为一条通知"你错过了 N 个提醒"，点击打开主窗口"今天"视图；
  - 超过 24 小时的：不补发，仅标记为已错过；
  - 已完成或已删除事项的提醒不补发。
- AC：休眠 1 小时期间到期的 2 个提醒，在唤醒后 10 秒内分别补发。

**FR-REM-08 已完成事项不提醒** — M

## 5 非功能需求

### 5.1 性能

| ID | 需求 | 指标 | 测量方法 |
|---|---|---|---|
| NFR-PERF-01 | 仅托盘常驻内存 | 所有进程合计 ≤ 80 MB | 关闭主窗口与悬浮窗 10 分钟后，任务管理器"内存（专用工作集）"合计 |
| NFR-PERF-02 | 托盘 + 悬浮窗内存 | ≤ 130 MB | 同上，开启悬浮窗 |
| NFR-PERF-03 | 主窗口打开内存 | ≤ 250 MB | 1000 条事项、主窗口在"全部"视图 |
| NFR-PERF-04 | 空闲 CPU | 平均 < 0.5%，无周期性唤醒尖峰（> 1 次 / 分钟） | 后台常驻 1 小时采样 |
| NFR-PERF-05 | 冷启动 | 启动到主窗口可交互 ≤ 2 s | 4 GB 内存、SSD 设备 |
| NFR-PERF-06 | 操作响应 | 勾选、新建、切换视图 ≤ 100 ms；统计页加载 ≤ 500 ms | 1 万条完成记录 |
| NFR-PERF-07 | 容量 | 10 000 条事项、100 000 条完成记录、500 个标签下满足上述指标 | 造数测试 |
| NFR-PERF-08 | 长期运行 | 连续运行 7 天内存增长 ≤ 20% | 长稳测试 |
| NFR-PERF-09 | 安装包 | ≤ 90 MB | Windows NSIS 安装包大小 |

> 内存指标在 P3 技术验证中实测；若框架基线无法满足，经评审后调整并更新本 SRS。

### 5.2 可靠性

- NFR-REL-01 数据写入使用事务，异常断电或进程被杀后数据库不损坏，最多丢失最后 1 秒的编辑。
- NFR-REL-02 数据库损坏时，程序启动应检测并提示从最近自动备份恢复。
- NFR-REL-03 数据库结构升级应自动迁移，升级前自动备份；迁移失败时回滚并提示。
- NFR-REL-04 主窗口渲染异常不影响后台提醒与托盘；后台未捕获异常写入本地日志并尽量自恢复。

### 5.3 可用性与可访问性

- NFR-USE-01 新用户无需说明即可在 30 秒内完成"新建带提醒的事项"。
- NFR-USE-02 浅色与深色模式下正文文字对比度 ≥ 4.5:1，图标与控件边界 ≥ 3:1（WCAG 2.2 AA）。
- NFR-USE-03 所有交互元素有可见焦点样式；支持 Windows 屏幕阅读器读出单选框状态与事项标题。
- NFR-USE-04 尊重系统"减少动画"设置；动效时长 ≤ 300 ms。
- NFR-USE-05 支持 100%–200% 系统缩放，界面无错位与模糊。

### 5.4 安全与隐私

- NFR-SEC-01 数据仅保存在本机，不收集、不上传任何用户数据或遥测。
- NFR-SEC-02 渲染进程启用上下文隔离与沙箱，禁用 Node 集成，配置严格 CSP，仅通过白名单接口访问后台。
- NFR-SEC-03 导入文件需校验格式与版本，拒绝非法内容并给出错误提示。

### 5.5 可移植性与可维护性

- NFR-POR-01 代码在 Windows、macOS、Linux 上可构建；平台相关功能（通知按钮、托盘）集中封装。
- NFR-MNT-01 业务逻辑（循环计算、今日口径、统计聚合、提醒调度）为纯函数 / 独立模块，单元测试覆盖率 ≥ 80%。
- NFR-MNT-02 UI 颜色、字号、间距等全部来自设计令牌，禁止硬编码。

| 实体 | 关键属性 |
|---|---|
| Todo | id、标题、备注、截止日期、截止时间、是否全天、循环规则、循环结束条件、状态（未完成 / 已完成）、完成时间、优先级、手动排序值、创建 / 更新 / 删除时间 |
| Tag | id、父 id、名称、颜色、同级排序值、物化路径 |
| TodoTag | 待办 id、标签 id |
| Reminder | id、待办 id、类型（相对 / 绝对）、偏移分钟或绝对时刻、下次触发时刻、上次触发时刻、稍后至 |
| CompletionLog | id、待办 id、实例日期、完成时间、标题快照、标签快照 |
| Setting | 键、值 |

- DR-01 完成记录保存 **标题与标签快照**，保证事项修改或删除后历史统计仍可显示。
- DR-02 所有时间以 ISO 8601 本地时间 + 时区偏移存储；日期类字段以 `YYYY-MM-DD` 存储。

### 6.2 数据保留

- DR-03 回收站事项保留 30 天后永久删除。
- DR-04 完成记录永久保留，除非对应事项被永久删除。
- DR-05 自动备份保留最近 7 份。

### 6.3 导入导出格式

- DR-06 JSON 结构：`{ app: "XTodoY", schemaVersion, exportedAt, todos[], tags[], todoTags[], reminders[], completionLogs[], settings{} }`；导入时支持当前及更早的 `schemaVersion`。

## 7 用例

### 7.1 参与者

- 用户：使用软件的个人；
- 系统时钟 / 操作系统：触发提醒、电源与主题事件。

### 7.2 用例图

```
           ┌──────────────────────────────────────────┐
           │                 XTodoY                   │
  用户 ────┼── UC-01 快速记录待办                     │
     │     ├── UC-02 设置时间、循环与提醒              │
     │     ├── UC-03 勾选完成待办                      │
     │     ├── UC-04 响应提醒通知 ◄──────────────┐     │
     │     ├── UC-05 按标签整理与浏览             │     │
     │     ├── UC-06 管理标签树                  │     │
     │     ├── UC-07 通过悬浮窗查看并回到主界面   │     │
     │     ├── UC-08 查看完成统计                │     │
     │     └── UC-09 切换主题 / 修改设置          │     │
           │                                    │     │
 操作系统 ─┼── UC-10 后台调度与补发提醒 ─────────┘     │
           └──────────────────────────────────────────┘
```

### 7.3 主要用例描述

**UC-02 设置时间、循环与提醒**
- 前置：存在一条待办。
- 主流程：① 用户单击待办打开详情面板；② 设置截止日期为明天 9:00；③ 设置循环"每周一、三、五"；④ 添加提醒"提前 15 分钟"；⑤ 关闭面板，列表显示日期、循环与提醒图标。
- 扩展：2a 用户选择"全天"→ 提醒基准为全天事项默认提醒时间；3a 未设日期直接选循环 → 自动以今天为首个实例。
- 后置：调度器登记下一次提醒。

**UC-03 勾选完成待办**
- 主流程：① 用户单击待办前的单选框；② 系统写入完成记录，显示完成动画与撤销提示条；③ 悬浮窗与托盘计数更新。
- 扩展：2a 循环事项 → 日期前进到下一实例（FR-REC-05）；2b 用户 5 秒内点击"撤销"→ 恢复原状态并删除完成记录。

**UC-04 响应提醒通知**
- 前置：程序在后台运行，主窗口已关闭。
- 主流程：① 提醒时刻到达，系统通知弹出；② 用户点击「完成」；③ 事项完成，悬浮窗计数减一。
- 扩展：2a 点击「稍后提醒」→ 10 分钟后再次通知；2b 点击通知正文 → 打开主窗口并定位事项；2c 用户未处理 → 通知留在操作中心。

**UC-07 通过悬浮窗查看并回到主界面**
- 主流程：① 用户看到悬浮窗显示"3"；② 悬停查看"今日已完成 2 / 共 5"；③ 单击悬浮窗；④ 主窗口显示并切换到"今天"视图。
- 扩展：1a 拖动悬浮窗到屏幕左上角，松开后位置被保存。

**UC-10 后台调度与补发提醒**
- 主流程：① 电脑睡眠，期间 2 个提醒到期；② 电脑唤醒，系统通知程序；③ 程序检查错过的提醒并在 10 秒内补发。
- 扩展：3a 错过超过 3 条 → 合并为一条"你错过了 N 个提醒"。

## 9 已确认的决策

以下为 SRS 阶段对原始需求模糊点作出的决定，已于 v1.0 评审确认（D-1、D-9 按评审意见修改）：

| # | 主题 | 默认决定 | 所在需求 |
|---|---|---|---|
| D-1 | 今日待办口径 | 仅今天到期（不含逾期、不含无日期）；悬浮窗显示未完成数 | FR-FLT-03, FR-TODO-05 |
| D-2 | 循环完成语义 | 单条记录日期前进；按原计划日期计算下一次；逾期错过的实例直接跳过 | FR-REC-05 |
| D-3 | 月末无效日期 | 落到当月最后一天 | FR-REC-04 |
| D-4 | 错过提醒补发 | 24 小时内补发，> 3 条合并；更早不补发 | FR-REM-07 |
| D-5 | 删除父标签 | 让用户选择子标签上移或一并删除；事项只解除关联 | FR-TGM-04 |
| D-6 | 标签层级上限 | 5 级；单事项最多 10 个标签 | FR-TAG-01/02 |
| D-7 | 删除事项 | 软删除进回收站，保留 30 天 | FR-TODO-04 |
| D-8 | 周起始日 | 默认周一，可设置 | FR-SET-05 |
| D-9 | 全天事项提醒基准 | 默认 08:30，可设置 | FR-SET-04 |
| D-10 | 统计归属 | 按完成时间所在本地日期；删除事项保留历史完成记录 | FR-STA-01 |
| D-11 | 关闭按钮 | 默认关闭到托盘，可改为退出 | FR-BG-02 |
| D-12 | 悬浮窗默认 | 默认开启，初始位置主显示器右下角 | FR-FLT-01/04 |
