# XTodoY 项目规划

> 版本：v0.3（规划稿，补充自动更新） · 日期：2026-11-02 · 仓库：https://github.com/AhDaii/XTodoY.git

## 1. 项目概述

XTodoY 是一款面向 PC 桌面端的待办事项管理软件，主打 **轻量常驻、按时提醒、多级标签分类、完成统计**。

### 1.1 核心功能范围

| 编号 | 功能模块 | 说明 |
|---|---|---|
| F1 | 待办管理 | 新建 / 编辑 / 删除待办；每项前有单选框（圆形勾选框），用户手动勾选完成 / 取消完成 |
| F2 | 时间与循环 | 设置事项日期 / 时间（可仅日期、可全天）；循环规则：每天 / 每周（指定星期）/ 每月（指定日）/ 每年 / 自定义间隔（RRULE 子集） |
| F3 | 提醒 | 每个事项可设置一个或多个提醒时间（准时、提前 N 分钟 / 小时 / 天、自定义时间点）；默认通过系统通知渠道（Windows Toast，macOS / Linux 走各自系统通知）推送；通知支持「完成」「稍后提醒」 |
| F4 | 标签 | 待办可挂多个标签；标签支持多级（父子树）；按标签分类浏览，选中父标签时包含子标签事项 |
| F5 | 标签管理 | 标签的增删改、重命名、颜色、拖拽排序与调整层级、合并、删除时处理关联事项 |
| F6 | 后台常驻 | 关闭主窗口后最小化到系统托盘继续运行；单实例运行；开机自启（可选）；低 CPU / 内存占用 |
| F7 | 悬浮窗 | 置顶小窗显示「今日待办数量」（未完成 / 总数）；可拖动、位置记忆、可开关；单击悬浮窗唤起并聚焦主界面 |
| F8 | 统计 | 按 天 / 周 / 月 统计已完成事项数量与明细；趋势图、按标签分布、完成率 |
| F9 | 外观 | 浅色 / 深色 / 跟随系统 三种主题 |
| F10 | 更新 | 自动 / 手动检查新版本，后台下载并校验，提示"重启以更新"或在退出时安装；可关闭（SRS v1.1 新增） |

### 1.2 非功能目标（初定，SRS 阶段细化）

| 指标 | 目标值 |
|---|---|
| 仅托盘常驻（无任何窗口）总内存 | ≤ 80 MB |
| 托盘 + 悬浮窗总内存 | ≤ 130 MB |
| 主窗口打开时总内存 | ≤ 250 MB |
| 空闲 CPU 占用 | ≈ 0%（无轮询，事件 / 定时器驱动），平均 < 0.5% |
| 冷启动到可交互 | ≤ 2 s |
| 提醒准时性 | 误差 ≤ 5 s；休眠唤醒后补发错过的提醒 |
| 安装包体积 | ≤ 90 MB |
| 支持平台 | Windows 10 / 11（主要）；macOS、Linux（次要，保持可构建） |

> 内存为所有进程（主进程 + 渲染进程 + GPU 进程等）之和，以任务管理器「提交大小 / 工作集」口径在 P3 Spike 中实测后定稿。

## 2. 技术选型

### 2.1 框架：Electron

选择 Electron 的理由：

- 主流跨平台桌面框架，生态最成熟，资料与第三方库最多；
- 全栈 TypeScript，前后端（主进程 / 渲染进程）同一语言，降低开发与维护成本；
- 托盘、系统通知、开机自启、单实例、电源事件、系统主题等能力均为内置 API。

代价是基础内存与安装包体积偏大，通过 §3.1 的「关窗即销毁、悬浮窗极简入口、事件驱动」等策略控制，并在 P3 阶段实测验证。

### 2.2 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 桌面框架 | Electron（当前稳定版） + electron-vite | 多入口构建（main / preload / 主窗口 / 悬浮窗） |
| 前端框架 | React 18 + TypeScript + Vite | 主窗口 |
| UI 样式 | Tailwind CSS + shadcn/ui（Radix） | CSS 变量实现设计令牌，`dark` class 切换深色模式 |
| 状态管理 | Zustand | 轻量 |
| 图表 | Recharts | 统计模块，按需懒加载 |
| 数据存储 | SQLite：better-sqlite3（WAL 模式）+ Drizzle ORM（schema 与迁移） | 本地单文件，位于 `app.getPath('userData')` |
| 循环规则 | `rrule`（RFC 5545 子集） | 便于未来与日历互通 |
| 系统集成 | `Tray`、`Notification`（Windows 用 `toastXml` 实现操作按钮）、`app.setLoginItemSettings`、`app.requestSingleInstanceLock`、`powerMonitor`、`nativeTheme` | 均为 Electron 内置 |
| 打包发布 | electron-builder（Windows NSIS 当前用户级安装包）+ electron-updater 自动更新 | 发布源为本仓库（公开）的 GitHub Releases |
| 测试 | Vitest + Testing Library（单元 / 组件）；Playwright `_electron`（E2E） | |
| 质量 | ESLint + Prettier、TypeScript strict、Husky + commitlint | |
| CI/CD | GitHub Actions：lint / test / 多平台构建 / Release 打包 | |
| 原型设计 | ui-ux-pro-max 插件 | 设计系统 + 高保真 HTML 原型 |
| 开发环境 | Node.js 22 LTS + pnpm | P3 搭建脚手架前安装 |

## 3. 架构设计（概要）

```
┌──────────────────────────── Electron App ─────────────────────────────┐
│  Renderer: 主窗口 (React)              Renderer: 悬浮窗 (原生 HTML/TS)  │
│   ├─ 待办列表 / 编辑                     └─ 今日待办数 · 点击唤起主窗口  │
│   ├─ 标签树 / 标签管理                                                  │
│   ├─ 统计                                                              │
│   └─ 设置                                                              │
│        ▲  window.api.*（preload contextBridge，类型化 IPC）  ▼          │
│  Main Process (Node)                                                   │
│   ├─ db:         SQLite 仓储（todos / tags / reminders / logs）          │
│   ├─ scheduler:  提醒调度器（最小堆 + 单个 setTimeout，无轮询）          │
│   ├─ recurrence: 循环实例生成                                           │
│   ├─ stats:      统计聚合查询                                           │
│   ├─ tray:       托盘图标、菜单与 tooltip                                │
│   ├─ notifier:   系统通知封装（含操作按钮）                              │
│   └─ windows:    主窗口 / 悬浮窗生命周期管理                             │
└───────────────────────────────────────────────────────────────────────┘
```

### 3.1 关键设计要点

- **低占用常驻**
  - 关闭主窗口时 **销毁** BrowserWindow（而非隐藏），仅保留主进程 + 托盘 + 可选悬浮窗；从托盘 / 悬浮窗打开时再创建。
  - 悬浮窗为独立的原生 HTML + 少量 TS 入口，不加载 React 主包，渲染进程尽量小。
  - 关闭拼写检查等不需要的功能；统计图表等重模块按需懒加载；后台窗口启用 `backgroundThrottling`。
  - P3 实测 GPU 进程开销，决定是否对悬浮窗场景禁用硬件加速。
- **提醒调度**：所有未触发提醒放入按触发时间排序的最小堆，只挂一个睡到最近触发点的 `setTimeout`；数据变更时重算。监听 `powerMonitor` 的 `resume` 与系统时间变化，唤醒 / 启动后补发错过的提醒（多条合并为一条通知）。
- **循环事项**：事项保存 RRULE；勾选完成时写入完成记录并按规则生成下一次实例（"完成即生成下一条"模型），统计以 `completion_logs` 为准。
- **多级标签**：`tags(id, parent_id, name, color, sort, path)`，`path` 为物化路径（如 `/1/4/9/`）便于"含子标签"查询；`todo_tags` 多对多关联。
- **今日待办数**：主进程计算并维护，在数据变更与跨零点时通过 IPC 推送给悬浮窗并更新托盘 tooltip，悬浮窗不自行轮询。
- **深色模式**：设计令牌以 CSS 变量定义浅 / 深两套取值；"跟随系统"时监听 `nativeTheme.on('updated')` 并同步到所有窗口。
- **安全**：`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`、严格 CSP；渲染进程只能通过 preload 暴露的白名单 API 访问主进程。

### 3.2 数据模型（初稿，SRS / 设计阶段定稿）

| 表 | 主要字段 |
|---|---|
| `todos` | id, title, note, due_date, due_time, all_day, rrule, status, completed_at, priority, sort, created_at, updated_at, deleted_at |
| `tags` | id, parent_id, name, color, sort, path |
| `todo_tags` | todo_id, tag_id |
| `reminders` | id, todo_id, offset_minutes / fire_at, fired_at, snoozed_until |
| `completion_logs` | id, todo_id, occurrence_date, completed_at（统计数据源） |
| `settings` | key, value |

- **远程仓库**：`https://github.com/AhDaii/XTodoY.git`
- **分支模型**：
  - `main`：稳定版本，仅通过 PR 合入，每次发布打 tag（如 `v1.0.0`）
  - `develop`：日常集成分支
  - `feature/<模块>`、`fix/<问题>`、`docs/<文档>`：从 `develop` 切出，完成后 PR 合回
- **提交规范**：Conventional Commits，例如 `feat(todo): 支持循环事项`、`docs(srs): 补充提醒补发需求`
- **阶段标签**：`srs-v1.0`、`design-v1.0` 等文档里程碑同样打 tag，便于追溯
- **Issue 管理**：每个阶段对应一个 Milestone，任务拆为 Issue，PR 关联 Issue

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Electron 多进程基础内存偏高 | 常驻指标不达标 | 关闭即销毁主窗口；悬浮窗极简入口；P3 Spike 实测，必要时评审调整指标或优化 GPU 进程开销 |
| Windows 通知在专注助手 / 勿扰模式下被屏蔽 | 用户错过提醒 | 设置页提示；可选应用内提醒弹窗作为补充渠道 |
| 休眠、关机期间提醒丢失 | 提醒不可靠 | 唤醒 / 启动时扫描错过的提醒并补发（合并通知） |
| 循环规则与时区 / 夏令时边界问题 | 时间错乱 | 统一以本地时区规则计算 + 边界单元测试 |
| better-sqlite3 原生模块与 Electron 版本不匹配 | 打包后无法运行 | 使用 electron-builder `install-app-deps` 重建；CI 固定 Electron 与 Node 版本 |
| 需求蔓延（同步、协作等） | 延期 | v1.0 范围以 SRS 冻结为准，新需求进入 Backlog |
| GitHub 在国内访问不稳定 | 部分用户检查 / 下载更新失败 | 失败静默重试并提供手动下载入口（SRS FR-UPD-09）；必要时增加国内镜像（如对象存储）作为备用发布源 |
| 未取得代码签名证书 | SmartScreen 警告、无法校验发布者 | 发布前申请证书；在此之前仅做 SHA-512 校验并在发布说明中提示 |
| 更新安装中断或迁移失败 | 程序无法启动或数据损坏 | 更新前备份、迁移失败回滚、当前用户级安装避免权限问题（SRS FR-UPD-07 / 09） |
